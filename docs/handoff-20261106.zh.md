## 2. 驱动集成方式

触摸驱动不是 `.ko`，而是 built-in：

```text
CONFIG_TOUCHSCREEN_NT36XXX_ML=y
```

编译链路：

```text
nt36xxx_core.c / nt36xxx_spi.c
  -> drivers/input/touchscreen/nt36xxx-ml/built-in.a
  -> arch/arm64/boot/Image
  -> payload
  -> sky-shim-boot-v4.img
```

触摸固件不是内核内置，而是运行时从 rootfs 加载：

```text
/lib/firmware/novatek/nt36672c.bin
```

当前设备固件版本：`0x18`。

网络和 SSH 由内置 initramfs `initramfs-m2` 提供，启动后挂载 UFS 并切换到 `/mnt/skyroot`。

## 3. 4 GB 内存修复

原来 DTS 仅描述：

```dts
reg = <0x0 0x80000000 0x0 0x68e00000>;
```

因此 Linux 只有约 1.1 GB 可用内存。

当前 `/memory` 使用 4 GB 设备的多段内存：

```dts
memory@80000000 {
    device_type = "memory";
    reg = <0x0 0x80000000 0x0 0x68e00000>,
          <0x0 0xf1300000 0x0 0x0ed00000>,
          <0x8 0x00000000 0x0 0x3fe00000>,
          <0x8 0x40000000 0x0 0x3c700000>,
          <0x8 0x7cd00000 0x0 0x01e00000>;
};
```

实机验证：

```text
free -m
Mem: total 3259 MB
```

启动日志对应约 3.2 GB 可用内存，说明内存 DTS 修复有效。

## 4. USB 网络修复

启用高端内存后，USB gadget 曾出现：

```text
dwc3-qcom a600000.usb: unknown endpoint event 0
```

原因是 DWC3 没有声明对应的 SMMU/IOMMU DMA 映射。当前 USB 节点包含：

```dts
iommus = <&apps_smmu 0x540 0x0>;
dma-coherent;
```

`0x540` 是 vendor DT 和同系列 Qualcomm DTS 使用的 DWC3 SID。

网络由 initramfs 创建：

```text
usb0 = 192.168.7.1/24
DHCP = 192.168.7.10–192.168.7.50
SSH = root
```

设备可通过：

```sh
ssh root@192.168.7.1
```

## 5. 触摸硬件和 DTS

触摸控制器：

```text
Novatek NT36672C
SPI: spi@a84000, CS0, mode 0
IRQ: GPIO13, rising edge, threaded IRQ + ONESHOT
Reset: 不使用 GPIO12，使用 SPI soft reset
Panel: 1080x2460
```

DTS 关键配置：

```dts
spi-max-frequency = <4000000>;
interrupts = <13 IRQ_TYPE_EDGE_RISING>;
touchscreen-size-x = <1080>;
touchscreen-size-y = <2460>;
novatek,swrst-n8-addr = <0x3f0fe>;
```

GPIO12 不再作为 reset-gpios 申请。原厂驱动也不申请该 GPIO，触控复位由 SPI 命令完成。

## 6. 固件下载和启动状态

正常启动时应看到一次：

```text
sky-fw: part 0 ILM ...
sky-fw: part 1 DLM ...
sky-repair: ... bad=0
sky-crc: flag=0x04
sky-fwinfo: fw_ver=0x18
sky-report[0]: 777777777777 state=a3...
```

`0xa3` 表示健康运行状态，`0x77` 是正常空闲报文。

此前启动阶段存在过：

```text
fwinfo 成功 -> 0xfe 报文 -> sky-recover -> 重复下载
```

已修复首帧等待逻辑：

- 不再把任意非 `fd/fe` 数据当作可用首帧；
- 等待真实 `0x77` 空闲帧或有效触摸报文；
- 最长等待约 500 ms；
- 首帧未就绪时不设置 `DOWNLOAD_COMPLETE`，避免立刻打开 IRQ 触发假恢复。

## 7. 运行期触摸恢复

曾观察到一次运行期异常：

```text
sky-recover[1]: reports all 0xFD/0xFE
sky-fwhist: fefefefe...
```

之后约 1.3 秒内重新下载固件并恢复：

```text
sky-fwinfo: fw_ver=0x18
sky-report: 777777...
state=a3...
```

当时 SPI 统计为：

```text
errors=0
timedout=0
```

因此这不是普通 SPI 传输错误，而是触控 IC 运行期进入 FD/FE reset 状态。当前恢复机制有效，但如果后续再次频繁出现，应继续调查触控供电、ESD/watchdog、显示电源切换和 SPI 时序。

DTS 还增加过 panel 1.8V：

```dts
regulator-always-on;
```

对应镜像是 `sky-shim-boot-v4-touch-powerfix.img`；最终推荐镜像 `touch-usbdma4g` 包含该 DTS 修改。

## 10. 后续注意事项

1. 不要把触摸驱动改成模块，当前 boot 流程依赖 built-in 驱动。
2. 不要恢复单段 1.6 GiB `/memory`，否则会再次出现 `free -m` 约 1.1 GB。
3. 如果修改高端内存段，必须同时验证 DWC3 IOMMU/DMA，否则可能复现 `unknown endpoint event 0`。
4. 刷写 boot 前确认当前 slot，避免误刷未启动的槽位。
5. 触摸首次下载只应出现一次；运行期偶发一次 FD/FE 恢复目前可以自动恢复，但连续频发需要单独调查。
6. `sky-shim-boot-v4.img` 是构建脚本的通用输出名，最终可交付文件使用带功能后缀的副本，避免覆盖和混淆。
