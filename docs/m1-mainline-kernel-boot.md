# M1 — mainline kernel boots to user space

**Result:** Linux 7.3 boots on `sky` with our own device tree, brings up
`simpledrm` + `fbcon` on the framebuffer ABL left behind, runs `/init` from an
embedded initramfs, and survives long enough to be driven over USB later.

## Kernel base choice

The community reference is ROCKNIX's SM4450 support (Retroid Pocket Classic,
Anbernic RG55G1). Their kernel is **Linux 7.2.11 + 48 patches**.

During bring-up we first used **Linux 7.3** because the audit had already been
done against it, then switched the plan to 7.2.11 as the "safe" base. Both were
built; the milestone results below are from the 7.3 tree, because that is where
all the debugging happened. See `docs/rocknix-patch-audit.md` for the patch
classification and the two places where 7.3 needed a rebase.

Applied series (only what the SoC needs to reach user space):

* interconnect, rpmhpd, rpmh regulator (PM6450), pd-mapper, remoteproc,
  arm-smmu, clk (dispcc/gpucc), serial/geni, pinctrl, and the UFS PHY tables.
* Two patches needed a manual rebase for 7.3:
  1. **UBWC** — the table format was refactored into shared descriptors.
  2. **RPMH PBS** — `RPMH_REGULATOR_REG_PBS_ENABLE` moved to another header.

## Device tree

`dts/sm4450-xiaomi-sky.dts` is generated by `tools/mksky_dts.py` from
ROCKNIX's `sm4450-anbernic-rg55g1.dts` (same SoC, same reference memory map),
with the board-specific parts replaced by values read out of **sky's own
runtime DT** (`fastboot getvar all`, `/proc/device-tree` dumps, vendor DTB
extracted from `vendor_boot`).

Key nodes that had to be added/fixed for the first boot:

* `/memory@80000000` — `0x80000000 + 0x68e00000` (1.6 GiB low bank). Without it
  the kernel has no RAM at all; arm64 board files do not describe memory.
* `/chosen/framebuffer@b8000000` — a `simple-framebuffer` node describing the
  splash region ABL leaves scanning out. This is what gives us a console.
* `/chosen/bootargs` — `console=tty0 fbcon=nodefer nokaslr panic=15
  clk_ignore_unused pd_ignore_unused`.

## What actually broke, and why

### 1. `simple-framebuffer` was rejected

```
simple-framebuffer b8000000.framebuffer: [drm] *ERROR* framebuffer size of
10627200 exceeds memory range [mem 0xb8000000-0xb8a223ff]
```

`reg` was exactly `1080*2460*4 = 0xa22400` bytes, and the driver compares the
computed size against the resource size. Giving the node the **whole 43 MiB
splash region** (`0x2b00000`) fixed it and `simpledrm` bound, which is what
turns on `fbcon`.

### 2. The display went grey/white a few hundred ms into boot

ABL leaves the DSI clocks running. Linux' clock framework then runs
`clk_disable_unused()` and switches off everything nobody claimed — including
the DSI/dispcc clocks that keep the panel scanning. The panel loses its DSI
stream and shows a uniform grey field.

Because `DRM_MSM` is not part of the first milestone, nothing claims those
clocks, so the fix is the standard escape hatch:

```
clk_ignore_unused pd_ignore_unused
```

### 3. TLMM: TrustZone-protected GPIOs kill the pinctrl probe

`gpiochip_add_data()` reads the direction of **every** valid pin. A few TLMM
register pages on SM4450 are XPU-protected; reading them raises a
**synchronous external abort** (ESR `0x96000010`), and that is *not* fixable
through the exception table — `copy_from_kernel_nofault()` oopses as well:

```
pc : copy_from_kernel_nofault+0x6c/0xeb
Call trace:
  copy_from_kernel_nofault
  msm_gpio_get_direction
  gpiochip_add_data_with_key
  msm_pinctrl_probe
  sm4450_tlmm_probe
```

The working workaround (`kernel/patches/0001-…`) is to not expose
`get_direction` at all during registration, so gpiolib skips the probe loop:

```c
	pctrl->chip.get_direction = NULL;
```

The proper long-term fix is `gpio-reserved-ranges` in the TLMM node once the
exact protected pins are known (the vendor DT does not describe them either).

## Early-boot debugging that made this possible

Without UART the kernel was a black box. Two mechanisms were added
(`kernel/patches-debug/`):

1. **Progress markers** — `sky_dbg_mark(n)` in `init/main.c` paints a 64×64
   block into the framebuffer at ~20 well-known points (`mm_core_init`,
   `sched_init`, `init_IRQ`, `time_init`, `console_init`, `rest_init`, the
   initcall tail, `free_initmem`, `mark_readonly`, `pti_finalize`, …).
2. **Panic painting** — on panic the whole screen is filled with the **colour of
   the last stage reached**, plus a red bar, so a photo tells you where it died.

A typical find: the "hang" was our own marker writing at `y = 300 + 24*90 =
2460` on a 2460-line framebuffer — one row past the end — which faulted inside
`kernel_init()`. The kernel was fine; the instrumentation was not.

## Boot arguments that matter

```
console=tty0 fbcon=nodefer nokaslr panic=15 clk_ignore_unused pd_ignore_unused
```

* `nokaslr` — the shim always loads at a fixed address; KASLR only gets in the
  way while debugging.
* `fbcon=nodefer` — take the framebuffer console over immediately.
* `clk_ignore_unused pd_ignore_unused` — keep ABL's display clocks alive.
* `panic=15` — enough time to photograph the screen.

## Reproducing

```bash
# kernel
tar xf linux-7.3.tar.xz && cd linux-7.3
../../rocknix-patches/apply.sh .        # the 48-patch series (see audit)
patch -p1 < ../sky-linux/kernel/patches/0001-pinctrl-msm-tolerate-tz-protected-gpios.patch
patch -p1 < ../sky-linux/kernel/patches/0002-ufs-qcom-add-sm4450-ufshc-compatible.patch
cp /path/sky-linux/kernel/configs/sky-m1.config .config
make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- olddefconfig Image

# dtb
cp /path/sky-linux/dts/sm4450-xiaomi-sky.dts arch/arm64/boot/dts/qcom/
echo 'dtb-$(CONFIG_ARCH_QCOM) += sm4450-xiaomi-sky.dtb' >> arch/arm64/boot/dts/qcom/Makefile
make ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu- dtbs

# pack + flash (see M0)
```

## Known gaps at this milestone

* No display driver (`DRM_MSM` off): the framebuffer console is the only output.
* No storage: rootfs lives in the kernel's embedded initramfs.
* No network: solved in M3.
* `arm-smmu 3da00000.iommu` (GPU) times out after 10 s; the GPU node is
  disabled in the DTS until the display/GPU work starts.
